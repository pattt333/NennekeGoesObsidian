## Context

The ZIP archive remains authoritative for rule text, and its Markdown output is regenerated by `nenneke_v2_pipeline.py`. The supplied design principles are editorial material outside that archive, so manual edits to generated chapter files would be lost on the next conversion.

## Goals / Non-Goals

**Goals:**

- Preserve the supplied editorial text in versioned Markdown source files.
- Display the overall principle before the rule chapters and the available chapter principles immediately after their chapter titles.
- Keep navigation and PDF generation compatible with the generated material.

**Non-Goals:**

- Invent a principle for chapter 2, for which no text was supplied.
- Rewrite existing rule text or alter its ZIP-derived order.
- Convert the design material into a separate gameplay rules subsystem.

## Decisions

- Store editorial sources in `content/design-principles/`, outside the generated vault. This gives them a clear, editable source of truth without claiming they come from the ZIP.
- Use one overall source plus source files keyed by chapter number. The pipeline creates `grundideen-des-regeldesigns.md` and inserts available chapter content after the first H1 of the corresponding generated note.
- Present each chapter contribution as a `## Designprinzipien` section. The health source retains its supplied subheadings underneath that section.
- Add the overall page ahead of all numbered chapters on the generated home page and sidebar. This is more discoverable than putting the text only on the start page.

## Content and Link Impact

- Adds one generated top-level vault page and source-managed text at seven chapter entry points (1 and 3–9).
- Home and sidebar gain a link to the overall principles page; all links use relative Markdown paths that work in Obsidian and Docsify.
- The generated overview page is not a ZIP-derived rule note and is excluded from source-only migration detection.

## Risks / Trade-offs

- [Editorial source is omitted during generation] → Focused pipeline tests assert the overview and chapter insertion behavior.
- [A future regeneration overwrites visible principles] → The generator always reads the versioned editorial source files before writing output.
- [Chapter 2 lacks a section] → No placeholder is rendered; a future source file automatically enables its section.

## Validation Strategy

- Run pipeline tests and validation, link and orphan validation, strict OpenSpec validation, and inspect the Docsify start page plus chapter 6.
